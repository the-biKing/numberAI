\begin{abstract}
    This document outlines the development, architecture, and findings of the \textbf{numberAI} project. The objective of this project is to recreate machine learning functionality from scratch, without relying on pre-trained models or established neural network structures. By utilizing simple matrix multiplication and a trial-and-error training approach, the project aims to categorize number images. Additionally, it details the planned second phase involving quantization and distillation for deployment on resource-constrained embedded systems such as Arduino.
\end{abstract}

\section{Introduction}
\subsection{Project Motivation}
Modern machine learning often relies on complex, pre-defined architectures and pre-trained weights. The motivation behind numberAI is to deconstruct this paradigm and build an image classifier from the absolute basics to fully understand the underlying mechanics of neural networks.

\subsection{Goals and Phases}
The project is divided into two main phases:
\begin{itemize}
    \item \textbf{Phase 1: Foundational Discovery.} To categorize number images using pure matrix multiplication. This phase avoids pre-defined structures, instead relying on trial and error to iteratively discover the optimal matrix size and network topology.
    \item \textbf{Phase 2: Embedded Systems Deployment.} To run the developed classification model on embedded systems with limited resources (e.g., Arduino). This requires applying model compression techniques such as \textit{quantization} and \textit{distillation} to reduce memory footprint and computational load.
\end{itemize}

\section{Phase 1: Architecture Iterations}
As the project employs a trial-and-error discovery method, the model architecture and training methodology evolved chronologically through multiple versions. This section documents the progression of the model, detailing the problems encountered in each version and the subsequent upgrades.

\subsection{Version 0: Initial Attempt}
The very first attempt (\textbf{Version 0}) served as a baseline to test the pure matrix multiplication concept without any additional complexity.

\subsubsection{Architecture and Methodology}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{./image/architectureV0.png}
    \caption{Version 0 Architecture}
    \label{fig:architectureV0}
\end{figure}
\begin{itemize}
    \item \textbf{Linear Topology}: The network consisted of two weight matrices ($H1$ and $H2$) with no activation functions between them.
    \item \textbf{I/O Inefficiency}: The training loop read and wrote the matrices to the disk at every single iteration.
\end{itemize}

\subsubsection{Results and Failures}
Version 0 was ultimately unsuccessful due to several critical flaws:
\begin{itemize}
    \item \textbf{Linearity Collapse}: Without a non-linear activation function, the two-layer network was mathematically pointless. Sequential linear matrix multiplications can be collapsed into a single matrix, meaning no deep representations were being learned.
    \item \textbf{Performance Bottleneck}: Reading and writing matrices to the disk at every step made the training process extremely slow.
    \item \textbf{Gradient Explosion}: The training never finished because the loss would eventually hit NaN due to gradient explosions. Consequently, no usable model was produced for testing.
\end{itemize}

\subsubsection{Points to Solve in Next Iteration}
\begin{itemize}
    \item Introduce a non-linear activation function (e.g., ReLU) to prevent linearity collapse and enable deep feature learning.
    \item Optimize the matrix disk read/write methodology to eliminate the severe I/O performance bottleneck during training.
\end{itemize}

\subsection{Version 1.0: Non-Linearity and Optimization}
To address the fatal flaws of Version 0, several major upgrades were introduced in \textbf{Version 1.0}.

\subsubsection{Architecture Upgrades}
The structure for Version 1.0 introduced non-linearity:
\begin{itemize}
    \item \textbf{Input Layer}: Flattened representation of the input image.
    \item \textbf{Hidden Layers}: Two primary weight matrices ($H1$ and $H2$). Dimensions were iteratively tested (e.g., $256 \times 32 \to 32 \times 10$, and later $4096 \times 128 \to 128 \times 10$).
    \item \textbf{Activation Function}: ReLU (Rectified Linear Unit) was introduced between the hidden layers to prevent the linearity collapse seen in Version 0.
    \item \textbf{Output Layer}: Vector of size $10 \times 1$, representing the classification scores for digits 0-9.
\end{itemize}

\subsubsection{Methodology Upgrades}
\begin{itemize}
    \item \textbf{Optimized I/O}: The matrix reading and writing methods were optimized to keep weights in memory during the training loop, massively speeding up training.
    \item \textbf{Numerical Gradient Training}: The loss function calculates the sum of Euclidean distances between the actual output vector ($\mathbf{A}$) and expected output ($\mathbf{EA}$):
          \begin{equation}
              \mathbf{Loss} = \sum_{k=0}^{9} \sqrt{\sum_{n=0}^{9} \left( A_{k,n} - EA_{k,n} \right)^2}
          \end{equation}
          The weight was then updated using a numerical gradient approximation (trial-and-error):
          \begin{equation}
              H_{m,n} := H_{m,n} - \left( \frac{\mathbf{Loss}_{o+\text{change}} - \mathbf{Loss}_{o}}{\text{change}} \right) \cdot \alpha
          \end{equation}
\end{itemize}

\subsubsection{Version 1.0 Training Results}
After training the Version 1.0 architecture, a measurable drop in Shannon entropy for the weight matrices was observed:
\begin{itemize}
    \item \textbf{Pre-training Entropy}: $H1 \approx 6.63$, $H2 \approx 6.45$
    \item \textbf{Post-training Entropy}: $H1 \approx 3.05$, $H2 \approx 3.23$
\end{itemize}
This lower entropy indicates that the trial-and-error process successfully converged on structured patterns within the dataset. A visualization of the training loss can be seen below:

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{./image/trainV1.png}
    \caption{Version 1.0 Training Loss Progression}
    \label{fig:trainV1}
\end{figure}

\textbf{Overfitting Discovery:}
While the training process converged, evaluating the model revealed a severe case of overfitting. The model successfully categorized all images in the training dataset, achieving an accuracy of 100.00\% (100/100). However, when exposed to new, unseen number images from the verification dataset, it completely failed, yielding an accuracy of 0.00\% (0/10). This indicates that the Version 1.0 architecture effectively memorized the specific pixels of the training data but failed to generalize the underlying visual features of the numbers.

\subsubsection{Points to Solve in Next Iteration}
\begin{itemize}
    \item Address the severe \textbf{overfitting} to ensure the model generalizes to unseen data instead of merely memorizing the training dataset.
    \item Improve \textbf{training efficiency}. The numerical gradient approach is far too slow (taking upwards of 15 minutes) for a model of this size.
    \item \textbf{Loss Function Singularity}: The Euclidean distance loss function uses a square root. Its derivative places the square root in the denominator, meaning as the loss approaches zero, it causes a divide-by-zero error leading to NaN gradient explosions. A loss function without this singularity (such as Mean Squared Error) is required.
\end{itemize}

\subsection{Version 1.1: Vectorized Blame Assignment (Backpropagation)}
To address the severe overfitting and slow training times observed in Version 1.0, the training methodology was significantly overhauled in \textbf{Version 1.1}. The numerical gradient approach (trial-and-error finite difference) was replaced with a heavily optimized, mathematically grounded blame assignment method.

\subsubsection{Methodology Upgrades}
The adjustment logic was optimized using vectorized blame assignment (backpropagation):
\begin{itemize}
    \item \textbf{H2 Adjustment}: The error vector is multiplied by the transposed middle neuron vector (from $H1$) to compute the gradient for all parameters of $H2$ simultaneously.
    \item \textbf{H1 Adjustment}: The error vector is multiplied by the transposed $H2$ matrix, passed through the derivative of the ReLU function, and then multiplied by the transposed input vector ($I$). This allows the simultaneous adjustment of all $H1$ parameters.
\end{itemize}
This vectorized approach eliminates the need to perturb weights one-by-one, replacing millions of individual forward passes with a single efficient backward pass.

\subsubsection{Version 1.1 Training Results}
The implementation of vectorized blame assignment yielded two major breakthroughs:
\begin{enumerate}
    \item \textbf{Blazing Fast Training}: The training time was drastically reduced to approximately 30.6 seconds (down from over 15 minutes in Version 1.0), completing 500 iterations over the entire dataset with ease.
    \item \textbf{Generalization over Memorization}: The updated weight adjustment logic successfully prevented the model from merely memorizing pixels. Evaluation metrics showed:
          \begin{itemize}
              \item \textbf{Training Dataset Accuracy}: 100.00\% (100/100)
              \item \textbf{Verification Dataset Accuracy}: 60.00\% (6/10)
          \end{itemize}
\end{enumerate}

    \centering
    \includegraphics[width=0.8\textwidth]{./image/trainV1.1.png}
    \caption{Version 1.1 Training Loss Progression}
    \label{fig:trainv1.1}
\end{figure}

\textbf{Learning Curve Analysis \& The Memorization Phase:}\\
As seen in Figure \ref{fig:trainv1.1}, the learning curve exhibits unusual behavior. The model initially learns rapidly, but quickly hits a plateau where the blame assignment algorithm no longer encounters novel information, even though the loss remains relatively high. Because the training dataset is severely limited (only 100 images), the model exhausts the generalizable patterns and enters a \textit{memorization phase}. Instead of learning the underlying features of the numbers, it begins to memorize the specific 100 images to force the loss lower. This perfectly explains why the training accuracy reaches 100\% while the verification accuracy stagnates at 60\%.

\subsubsection{Points to Solve in Next Iteration}
\begin{itemize}
    \item \textbf{Dataset Starvation}: The core cause of the memorization plateau is the extremely small dataset. The model needs a vastly larger and more diverse dataset to prevent it from memorizing and force it to continuously learn generalizable features.
    \item \textbf{Dynamic Stopping Condition}: Currently, training terminates after a hardcoded 500 iterations without evaluating the model's actual convergence state. The next version needs a dynamic stopping mechanism based on metrics such as Shannon Entropy, the slope of the loss, or the raw loss value itself.
    \item \textbf{Adaptive Learning Rate}: The learning rate parameters were chosen via arbitrary guessing. Incorrect learning rates caused several initial training attempts of Version 1.1 to fail. A systematic or adaptive method for determining the optimal learning rate is necessary for stable and reliable training.
\end{itemize}

\subsection{Version 1.2: Improved Dataset Generalization}
To address the generalization issues identified in Version 1.1, the training dataset was fundamentally upgraded in \textbf{Version 1.2}. The custom, small-scale dataset was replaced with the standardized MNIST dataset.

\subsubsection{Methodology and Results}
By training the model on the much larger and highly varied MNIST dataset, the model was exposed to a far wider array of handwriting styles. This significantly improved the model's ability to extract general features rather than memorizing specific pixels.
\begin{itemize}
    \item \textbf{Generalization Success}: The model achieved a highly promising \textbf{93.93\% accuracy} on the verification set, resolving the core overfitting issue from earlier versions.
\end{itemize}

\subsubsection{Points to Solve in Next Iteration}
\begin{itemize}
    \item \textbf{Shifted Number Problem}: While the model performs well on centered digits, its reliance purely on fully connected dense layers means it is highly sensitive to spatial translation. If a number is shifted off-center, the model struggles to categorize it accurately. A mechanism to introduce translation invariance is required.
\end{itemize}

\subsection{Version 1.2.1 \& 1.4.1: Scaling to Full Resolution}
To capture more detailed features, the input data was upgraded from the $16 \times 16$ MNIST subset back to the standard $28 \times 28$ resolution. 
\begin{itemize}
    \item \textbf{Architecture}: The input layer expanded from 256 to 784 neurons. Hidden layers were scaled up accordingly (e.g., $784 \to 36 \to 10$ for v1.2.1, and $784 \to 49 \to 10$ for v1.4.1).
    \item \textbf{Result}: The larger input space allowed the network to retain finer edge details, slightly improving accuracy compared to the 16x16 downscaled images.
\end{itemize}

\subsection{Version 1.3 \& 1.4: Hybrid Pooling Experiment}
While maintaining the $16 \times 16$ input, \textbf{Version 1.3} experimented with integrating a custom pooling operation alongside standard dense layers.
\begin{itemize}
    \item \textbf{Architecture}: The 256-pixel input was passed into a 16-neuron dense layer. Simultaneously, the raw $16 \times 16$ input underwent two passes of $2 \times 2$ max pooling, reducing it to a $4 \times 4$ grid (16 features). These pooled features were concatenated with the dense layer outputs, forming a 32-neuron bottleneck before the final classification layer.
    \item \textbf{Result}: This hybrid approach attempted to force the network to utilize both spatial maximums and dense correlations, though it remained limited by the lack of sliding convolutions.
\end{itemize}

\subsection{Version 1.5 \& 1.5.1: Deep Neural Network Transition}
To test the limits of the hand-written backpropagation algorithm, the architecture was significantly deepened in \textbf{Version 1.5}.
\begin{itemize}
    \item \textbf{Architecture}: The model transitioned from a single hidden layer to a three-hidden-layer topology ($784 \to 196 \to 49 \to 10$).
    \item \textbf{Result}: This demonstrated that the custom blame assignment math could successfully chain gradients through multiple layers (Deep Learning) without encountering vanishing gradients, achieving an impressive test accuracy of over 97\%.
\end{itemize}

\subsection{Version 1.6 \& 1.7: The 4-Branch Architecture}
To address the lack of spatial awareness inherent in simple dense layers, \textbf{Version 1.6} introduced a "Multi-Branch" topology. The input was processed through four parallel branches with varying dimensional reductions.
\begin{itemize}
    \item \textbf{Version 1.6 (Concatenation)}: The 4 branches (shapes: $784 \to 28$, $392 \to 14$, $112 \to 4$, $28 \to 1$) extracted features independently and concatenated them before the final output.
    \item \textbf{Version 1.7 (Element-wise Summation)}: Iterating on v1.6, this version standardized the output of the 4 branches to be uniform ($1 \times 28$). Instead of concatenation, the 4 branches were summed element-wise into a single 28-dimension vector before the final layer.
\end{itemize}

\subsection{Version 1.8: 7-Branch Geometric Slicing}
\textbf{Version 1.8} took the multi-branch concept further by physically slicing the $28 \times 28$ input into geometric regions, forcing different branches to specialize in different parts of the image.
\begin{itemize}
    \item \textbf{Architecture}: The image was sliced horizontally into four strips (each $28 \times 7$), passed through branches $H1\_1$ to $H1\_4$. Additionally, the top-center and bottom-center $14 \times 14$ regions were extracted and passed through branches $H1\_5$ and $H1\_6$. 
    \item \textbf{Feature Aggregation}: Along with the full flattened image ($H1$), all 7 branches outputted 28 features each, which were concatenated to form a 196-dimension feature vector. This vector was then passed into $H2$ ($196 \to 10$).
\end{itemize}

\subsection{Version 1.8.1: 12-Branch Spatial Expansion}
Building directly upon v1.8, \textbf{Version 1.8.1} drastically expanded the localized geometric feature extraction to capture the corners and absolute center of the image.
\begin{itemize}
    \item \textbf{Architecture Addition}: Five new branches ($H1\_7$ through $H1\_11$) were added. These branches specifically ingested $14 \times 14$ patches from the top-left, top-right, bottom-left, bottom-right, and absolute center of the $28 \times 28$ image. 
    \item \textbf{Result}: Each of the 12 total branches outputted 28 features, creating a massive 336-dimension bottleneck layer ($12 \times 28 = 336$). The final layer ($H2$) was scaled to $336 \times 10$. This approach maximized spatial awareness and local structure recognition using purely dense matrix operations and slicing, avoiding the computational overhead of sliding convolution windows.
\end{itemize}

\subsection{Version 2.0: Introduction of Convolution}
To solve the shifted number problem and reduce the overall model size, \textbf{Version 2.0} introduced a custom convolution operation before the fully connected layers.

\subsubsection{Architecture Upgrades}
\begin{itemize}
    \item \textbf{Convolutional Kernel}: A single $3 \times 3$ learnable kernel ($K$) was introduced. The input image ($28 \times 28$) is convolved with this kernel to produce a feature map.
    \item \textbf{Max Pooling}: A $2 \times 2$ max pooling layer was implemented to downsample the feature map, providing the desired translation invariance and reducing the dimensionality of the data before it enters the dense layers ($H1$ and $H2$).
\end{itemize}

\subsubsection{Version 2.0 Training Results}
The introduction of the convolutional kernel successfully enabled the model to handle shifted numbers, and it maintained an accuracy comparable to Version 1.2. However, this architecture introduced new bottlenecks:
\begin{itemize}
    \item \textbf{Computational Overhead}: The custom Python implementation of the convolution and pooling operations significantly increased the training time compared to the pure matrix multiplication of Version 1.2.
    \item \textbf{Feature Limitation}: Using only a single convolution kernel restricted the model to focusing on just one specific spatial characteristic (e.g., a single edge type or texture), preventing it from learning rich, multi-dimensional features.
\end{itemize}

\subsubsection{Points to Solve in Next Iteration}
\begin{itemize}
    \item \textbf{Optimize Training Speed}: The custom numpy convolution loops are too slow. A highly optimized framework backend is necessary for practical training times.
    \item \textbf{Expand Feature Extraction}: The architecture must support multiple convolution kernels simultaneously to capture diverse features (e.g., horizontal edges, vertical edges, curves).
\end{itemize}

\subsection{Version 2.1: PyTorch Optimization}
To address the computational bottlenecks of the custom numpy convolution implementation in Version 2.0, \textbf{Version 2.1} transitions the model to leverage the PyTorch framework, utilizing GPU acceleration (CUDA).

\subsubsection{Architecture and Methodology Upgrades}
By adopting PyTorch, the network successfully vectorizes its operations, replacing the slow Python loops from Version 2.0 with optimized tensor operations while preserving the exact same hand-written backpropagation math. This massive computational speedup allowed the architecture to be scaled:
\begin{itemize}
    \item \textbf{Multiple Kernels}: The model was successfully upgraded from a single kernel to using \textbf{8 convolution kernels}. This enables the network to simultaneously extract multiple distinct spatial features (edges, curves, etc.) from the input images.
    \item \textbf{Matrix Resizing}: The hidden layer dimensions were adjusted to accommodate the multi-channel output from the convolutional and max pooling layers, resulting in $H1$ expanding to $1352 \times 64$, and $H2$ adjusting to $64 \times 10$.
\end{itemize}

Future versions can explore adding a second convolutional layer (deepening the network) or introducing dropout to push the accuracy even higher.

\subsection{Version 3.0: CFNet (Asymmetrical Input Slicing)}
Because the Version 2.1 model was consistently pushing $\approx$95\% accuracy on the MNIST dataset, the training challenge was fundamentally upgraded to the vastly more complex \textbf{EMNIST} dataset (Extended MNIST, expanding the 10 numerical digits to 47 alpha-numeric classes). This forced a significant architectural upgrade.

\subsubsection{Architecture Upgrades (RFNet)}
\textbf{Version 3.0} introduces a highly novel architecture dubbed \textbf{RFNet} (Residual Factor Net).
\begin{itemize}
    \item \textbf{Asymmetrical Input Slicing}: Instead of treating the $28 \times 28$ image uniformly, RFNet mathematically factors the dimension 28. The input image is dynamically reshaped into multiple parallel branches using these factors: ($1 \times 784$, $2 \times 392$, $7 \times 112$, $14 \times 56$, and $28 \times 28$). Each branch is processed through its own dense weight matrix ($H1_1$ through $H1_5$). This allows the network to simultaneously "view" the input image through different spatial lenses and aspect ratios, dramatically enriching feature extraction.
    \item \textbf{Residual Connections}: Building upon the promising theoretical results of residual networks, a residual connection was introduced. The downscaled convolutional feature map is directly summed with the dense output from $H2$ prior to the final ReLU activation. This stabilizes the complex multi-branch network and ensures gradient preservation.
\end{itemize}

\subsection{Version 3.1: RAFNet (Residual Asymmetrical Factor Net)}
Building upon the conceptual foundation of Version 3.0, \textbf{Version 3.1} introduces the definitive "ultimate" architecture for Phase 1: \textbf{RAFNet}.

\subsubsection{Architecture Upgrades}
\begin{itemize}
    \item \textbf{Dual Convolutional Slicing}: Two layers of $3 \times 3$ convolutions (with 7 filter branches) are applied. By passing the $28 \times 28$ image through these unpadded layers, the spatial dimension is naturally reduced to $24 \times 24$. The number 24 has significantly more mathematical factors (1, 2, 3, 4, 6, 8, 12, 24) than 28, allowing for a much more granular and diverse asymmetrical factor slicing in the parallel branches.
    \item \textbf{Learnable Residual Weights}: Instead of a hardcoded 50/50 sum, the residual connection now utilizes an element-wise learnable weighted ratio vector (\texttt{W\_skip}). This allows the model to dynamically and spatially choose the importance of the residual information versus the dense output.
\end{itemize}

\subsubsection{Training Optimization}
\begin{itemize}
    \item \textbf{Adam Optimizer}: To support the scale of this model, the \textbf{Adam optimizer} was adopted. This successfully solved the "Gradient Volatility" problem observed in previous iterations and drastically reduced the need for manual hyperparameter tuning.
    \item \textbf{Hybrid Backpropagation}: Because standard PyTorch autograd does not correctly handle the novel feedback loop of this asymmetrical branching architecture, a custom hybrid backward propagation function was manually implemented to accurately calculate gradients across the factored slices.
\end{itemize}

\subsubsection{Results and Extreme Efficiency}
RAFNet proved to be an incredibly efficient architecture:
\begin{itemize}
    \item \textbf{EMNIST Accuracy}: The model consistently pushed $\approx$88-90\% Test Accuracy on the highly complex 47-class EMNIST dataset in just 10 epochs.
    \item \textbf{Parameter Efficiency}: The model achieves this impressive performance with only $\approx$175,000 parameters. This stands in stark contrast to standard large-scale CNN models, which often require vastly more parameters to achieve similar accuracy on this dataset, definitively proving the computational efficiency of the RAFNet design.
\end{itemize}

\section{Discoveries and Challenges}
\subsection{Model Selection via Relativistic Efficiency Analysis}
Following the implementation of Version 2.1, a critical architectural crossroad was reached: choosing between a resource-intensive model with slightly higher accuracy (8 kernels, 324s training) and a cheaper model with faster training time but slightly lower accuracy (1 kernel, 57s training).

In machine learning, achieving an accuracy increase from 94\% to 96\% requires exponentially more computational effort than jumping from 10\% to 12\%. This diminishing return perfectly mirrors the principles of Special Relativity, where accelerating an object closer to the speed of light requires increasingly more energy. To formally evaluate model efficiency, an analytical method was developed adapting the relativistic kinetic energy equation:
\begin{equation}
    E = \frac{mc^2}{\sqrt{1 - \frac{v^2}{c^2}}} - mc^2
\end{equation}

Within the context of neural network optimization, the variables are redefined as follows:
\begin{itemize}
    \item \textbf{Velocity ($v$)} represents the model's accuracy. Because an untrained model initialized with random weights naturally achieves a baseline 10\% accuracy on a 10-digit dataset, the raw accuracy is linearly normalized:
          \begin{equation}
              v_{acc} = \frac{\text{Accuracy} - 0.1}{0.9}
          \end{equation}
          Here, a perfect 100\% accuracy translates to $v_{acc} = 1.0$, conceptually equivalent to the speed of light ($c$).
    \item \textbf{Mass ($m$)} represents the baseline structural complexity or "action" of the number recognition task.
    \item \textbf{Energy ($E$)} represents the absolute computational cost of the model. In practical terms, this is quantified as: $\text{Parameter Size} \times \text{Run Time}$.
\end{itemize}

Because the exact value of the conceptual mass ($m$) is unknown, absolute energy calculations for a single model are impossible. However, when comparing two distinct models, relative scaling can be employed. By calculating the theoretical relativistic energy ratio required to achieve Model B's accuracy compared to Model A's accuracy, and checking that against the \textit{actual} computational cost ratio, true efficiency can be determined. For instance, if Model B requires 10x more theoretical energy (due to higher accuracy) but only incurs 2x more actual computational cost, Model B is objectively the more energy-efficient architecture.

\subsubsection{The "Escape Velocity" Constraint}
A mathematical flaw in pure efficiency analysis is that an extremely cheap, low-accuracy model might appear mathematically optimal but remain practically useless. Drawing inspiration from rocket engineering, an "escape velocity" constraint was established. The absolute minimum baseline for a model to be considered viable is an accuracy of \textbf{90\%}. Any model failing to reach this escape velocity is automatically disqualified from selection, regardless of its theoretical efficiency.

This relativistic analysis framework allows for highly objective, mathematically sound decisions when balancing model architecture tradeoffs, ensuring that added computational costs are truly justified by the resulting accuracy gains.
